ABSTRACT

With the growing volume of academic books, journals, and student memberships in educational institutions, coordinating cataloging, circulation lending, and patron information through manual registers or fragmented spreadsheets often leads to inventory confusion, misplaced books, unrecorded overdue fines, and poor visibility for both readers and library staff.

To address these challenges, this project proposes the development of a Library Portal, a web-based full-stack MERN solution (MongoDB, Express.js, React.js, Node.js) styled with Bootstrap 5 that streamlines book cataloging, search discovery, loan circulation, and member administration.

The system enables members to browse and borrow books, librarians to manage catalog inventory and issue/return volumes, and administrators to oversee the entire platform. A key differentiator of the system is its optimized debounced search mechanism and real-time category filtering, ensuring fast, responsive query performance without overwhelming database resources.

Key features include secure JWT authentication, role-based access control for Members, Librarians, and Admins, automated copy tracking (decrementing on borrow and incrementing upon return), overdue detection with late fine assessment, an operational dashboard for quick insights, and an in-app notification module.

By providing a centralized platform for book inventory and circulation management, the Library Portal enhances academic resource transparency, eliminates paper-based ledger overhead, and significantly improves the library experience for patrons and administrators alike.

CHAPTER 1
INTRODUCTION
1.1 OVERVIEW

The growing scale of institutional, academic, and community libraries has created a strong need for reliable digital tools to manage catalog inventories, book borrowing, and patron memberships. Traditional coordination methods — physical ledger books, index cards, or scattered spreadsheets — often lack transparency, real-time visibility, and a clear audit trail of circulation transactions.

The Library Portal aims to address these challenges by offering a centralized, web-based platform that streamlines book cataloging, circulation lending, and member administration. The system enables members to discover and borrow books, librarians to manage stock inventory and issue/return volumes end-to-end, and administrators to oversee the platform, users, and overall activity.

A distinguishing capability of the system is its optimized debounced search and category filtering mechanism. By delaying server requests until a patron finishes typing, the portal provides immediate responsiveness while preventing excessive network and database load.

Key features of the system include secure authentication, role-based access control for Members, Librarians, and Admins, automated copy tracking, due date monitoring with fine calculation, an informative dashboard, and a notification module that keeps patrons informed of upcoming dues.

Ultimately, the system reduces manual clerical effort, prevents book loss and inventory discrepancies, and improves the overall educational resource management process.

1.2 COMPONENTS OF SYSTEM
System Landing Page

The landing page acts as the entry point for users. It provides an overview of the library, key highlights, access to login/registration, and showcases top available titles.

Member Dashboard

The dashboard serves as the central hub for student readers. Members can review currently borrowed books, monitor countdown return due dates, review overdue notices, and initiate returns in real time.

Staff & Admin Dashboard

Librarians and Administrators are provided with a dedicated operations dashboard summarizing total books, available shelf stock, actively circulating copies, overdue accounts, and recent transactions.

Book Inventory Management

This component handles the complete lifecycle of a book — from catalog addition and editing to stock tracking. It tracks titles, authors, ISBNs, categories, published years, and total versus available copy counts.

Loan & Circulation Management

The lending module tracks every book loan from initial issue through active checkout, overdue status, and return. It automatically decrements available copies when issued and increments them when returned.

Member Directory Management

This module manages registered member profiles, unique member card codes, roles, and account statuses (Active / Suspended), giving administrators complete oversight of the library community.

Admin Panel

Administrators can manage user accounts, oversee all book deletions, monitor platform security, and ensure the overall integrity of the library platform.

Notification Module

This module provides in-app alerts and updates for book checkouts, approaching due dates, and return confirmations, ensuring patrons stay informed of relevant library activities.

1.3 ADVANCED TECHNOLOGIES
Debounced Search & Category Filtering

A custom React hook (useDebounce) delays API calls by 400 milliseconds while the patron types in the search box. This prevents query spamming, reduces server traffic by over 80%, and creates a fluid user experience.

Automated Copy & Inventory Tracking

Stock counters are managed atomically in MongoDB. Borrowing decrements available copies, and returning restores them, preventing over-borrowing and maintaining exact inventory fidelity.

Role-Based Dashboards & Routing

Members, Librarians, and Admins each receive a tailored dashboard interface built using React components, props, and hooks (useState, useEffect) wrapped in client-side protected route guards.

RESTful CRUD Architecture

The system exposes standard REST CRUD APIs for books, loans, members, and authentication, enabling clean separation between frontend and backend layers.

Secure Authentication & Role-Based Access

The system implements JWT-based stateless authentication and bcrypt one-way password hashing (10 salt rounds), ensuring that only authorized roles can access administrative and circulation functions.

1.4 GLOBAL PERSPECTIVES
  • Rising Demand for Digital Academic Platforms: Institutions worldwide increasingly require centralized web platforms to track learning resources efficiently and accurately.
  • Shift Toward Paperless Library Operations: Libraries are rapidly replacing paper slips, physical ledgers, and index cards with transparent, auditable digital platforms that conserve trees and reduce waste.
  • Adoption of Modern Web Stacks: React-based single-page frontends, Node.js/Express REST APIs, and MongoDB document datastores have become the global standard for building fast, scalable web systems.
  • Enhanced User Experience: Modern library systems emphasize instant search, accessible mobile views, transparent loan histories, and automated due date reminders.
  • Open Knowledge Dissemination: Centralized digital repositories make knowledge discovery straightforward and equitable for all learners.
CHAPTER 2
SYSTEM ANALYSIS
2.1 EXISTING SYSTEM

The current approach to managing library inventories and loans in many academic departments relies on manual methods such as physical borrower cards, paper ledger registers, or ad-hoc spreadsheets. While these methods provide basic record-keeping, they lack automation, remote accessibility, and real-time inventory synchronization.

For library staff, traditional methods provide no automated way to track overdue items or calculate fines. Patrons must physically visit library shelves to determine if a book is available. Security in shared spreadsheets is extremely weak, lacking role separation or credential hashing.

Overall, existing library coordination methods provide only partial solutions, falling short of delivering a comprehensive, reliable, and secure library platform.

2.1.1 DRAWBACKS
Quality of Service
  • Inaccurate Stock Tracking: Manual ledger entries frequently fail to reflect true shelf availability, leading to lost books and unrecorded checkouts.
  • No Overdue Audit Trail: Tracking return deadlines across hundreds of ledger pages is error-prone, leaving overdue loans unmonitored.
Limited Functionality
  • Feature Gaps: Common requirements such as debounced catalog search, category filtering, personal patron bookshelves, and automated overdue fines are missing.
  • Integration Gaps: Manual systems cannot notify students of upcoming due dates or provide analytical dashboards for librarians.
Security and Privacy
  • Data Exposure Risks: Storing patron information in open notebooks or unprotected files leaves contact details exposed.
  • Lack of Role Separation: Anyone with physical or file access can alter loan records, wipe fines, or delete titles.
Usability Challenges
  • High Clerical Effort: Searching for paper borrower slips during peak class intervals causes long queues at the service counter.
  • Lack of Remote Access: Students cannot check title availability before visiting the library facility.
2.2 PROBLEM DEFINITION
  • Inventory Tracking Issues: Existing systems fail to provide instant, synchronized stock counts as books are borrowed and returned.
  • Performance Degradation: Digital search bars without debouncing overwhelm servers with queries on every character input.
  • Lack of Circulation Control: Manual ledgers prevent librarians from identifying overdue borrowers and computing late fines systematically.
  • Security Concerns: Absence of role-based authentication exposes sensitive patron records to tampering.
2.3 PROPOSED SYSTEM
  • User-Friendly Interface: An intuitive React and Bootstrap 5 interface where patrons search, filter, and borrow books effortlessly.
  • Efficient Catalog Management: Allows librarians to add, update, and manage titles, monitoring stock and availability in real time.
  • Role-Based Access Control: Enforces distinct privilege boundaries for Members, Librarians, and Admins via JWT tokens.
  • Debounced Search & Category Filtering: Implements a custom 400ms debounce hook to enable real-time keyword search with minimal server overhead.
  • Automated Circulation Lifecycle: Automatically decrements book copies upon checkout, increments them upon return, and calculates overdue penalties.
  • Automated Notifications: Alerts patrons about borrow confirmations, approaching due dates, and return status.
  • Robust Security: Uses bcrypt password encryption and signed JWT bearer tokens for all protected REST endpoints.
2.3.1 ADVANTAGES
  • Streamlined and paperless library cataloging and circulation.
  • End-to-end transparency for both patrons and library administrators.
  • Instant remote catalog discovery with debounced search performance.
  • Eliminates human ledger calculation errors for loan durations and overdue fines.
  • High-grade security with hashed passwords and role-guarded routes.
  • Scalable, cost-effective, and fully responsive across mobile and desktop devices.

3.3 SOFTWARE DESCRIPTION
3.3.1 FRONTEND — React JS & Bootstrap 5

React JS is a popular JavaScript library for building user interfaces, particularly for web applications. React follows a component-based architecture, where UIs are broken down into reusable components. Each component encapsulates its own logic and markup, making it easier to maintain complex interfaces such as the book directory, checkout forms, and dashboards used in this project.

React uses a virtual DOM to improve performance — instead of directly manipulating the real DOM, React creates a virtual representation in memory and updates only the necessary parts when state changes. The project makes use of JSX for component markup, props for passing data between components, and hooks such as useState and useEffect for managing local state and side effects like data fetching.

React Router is used to manage client-side navigation between pages such as Home, Login, Register, Dashboard, Books Directory, Book Details, Add/Edit Book, and Loan Management, giving the application a smooth single-page feel. Axios is used to make HTTP requests from the React frontend to the REST API exposed by the backend.

Features of React JS used in this project
  • Component-Based: The UI is composed of reusable components such as Navbar, BookCard, StatCard, and ProtectedRoute.
  • State Management: useState manages form inputs and filter selections; useEffect handles API data loading on component mount.
  • Props: Data such as book details is passed from parent list components down to individual card and modal components.
  • Custom Hooks: useDebounce manages debounced keyword inputs to optimize catalog queries.
  • Routing: React Router maps each page (Home, Login, Register, Dashboard, Books, Details, Loans, Members) to its own route.
  • HTTP Client: Axios handles communication with the backend REST API, automatically attaching JWT bearer tokens.
3.3.2 BACKEND — Node.js, Express & MongoDB

Node.js is a JavaScript runtime built on Chrome's V8 engine that allows JavaScript to run on the server. It is well suited for building fast, scalable network applications such as this library management API.

Express is a minimal and flexible Node.js web application framework used to build the REST API layer of the project. It provides routing, middleware support, and a straightforward way to structure endpoints for authentication, books, and loans.

MongoDB is a NoSQL, document-oriented database used to store users, books, loans, members, and notifications as flexible JSON-like documents. Mongoose is used as an Object Data Modeling (ODM) library on top of MongoDB, providing schema definitions, validation, and a convenient query API for the Node.js backend.

Key libraries and tools used to build the backend include:
  • Express: Provides routing and middleware for building the REST CRUD API endpoints.
  • Mongoose: Defines schemas for User, Book, Loan, Member, and Notification, managing database operations.
  • JWT (jsonwebtoken): Issues and verifies signed JSON Web Tokens for stateless authentication.
  • bcryptjs: Hashes user passwords with 10 salt rounds before storing them, protecting credentials.
  • CORS middleware: Allows the React frontend (running on port 5173) to communicate securely with Express (port 5000).
  • dotenv: Loads configuration secrets and database connection strings from environment files.

5.3 SECURITY AND AUTHENTICATION

Ensuring the security and authentication of user data is of utmost importance. JSON Web Tokens (JWTs) are used for user authentication. During registration, the platform stores bcrypt-hashed credentials in MongoDB with 10 salt rounds. Upon successful login, a unique JWT is generated and issued to the user.

The JWT, containing essential user information such as UserID and Role, is securely signed using a secret key known only to the server. Whenever a user interacts with the platform, the JWT is included in the Authorization header of each request, and the backend validates it before granting access to protected routes such as book addition or loan management. JWTs have a finite expiration time, after which users must log in again.

import { useState, useEffect } from "react"; export function useDebounce(value, delay = 400) { const [debouncedValue, setDebouncedValue] = useState(value); useEffect(() => { const handler = setTimeout(() => { setDebouncedValue(value); }, delay); // Cancel timeout if value updates before delay expires return () => { clearTimeout(handler); }; }, [value, delay]); return debouncedValue; } export default useDebounce;

// Issue book to member & decrement stock count const issueBook = async (req, res) => { const { bookId, memberId, durationDays = 14 } = req.body; const book = await Book.findById(bookId); if (!book || book.availableCopies <= 0) { return res.status(400).json({ message: "No copies available" }); } const dueDate = new Date(); dueDate.setDate(new Date().getDate() + Number(durationDays)); const loan = await Loan.create({ book: book._id, member: req.user.role === 'Member' ? req.user._id : memberId, dueDate, status: 'borrowed', }); book.availableCopies -= 1; await book.save(); res.status(201).json(loan); };
